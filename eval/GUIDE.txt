================================================================================
OPF 한국어 PII 평가 — 실행 안내
================================================================================
이 문서는 개발망 자리에서 화면을 보며 읽는 용도입니다. 80자 폭 순수 텍스트.

--------------------------------------------------------------------------------
1. 이 테스트가 무엇인가
--------------------------------------------------------------------------------
공개 모델 OPF(Open Privacy Filter)가 한국어 상담 문장에서 개인정보를 얼마나
놓치는지 재는 시험입니다. 정답은 한국어 PII 3,000건(스팬 28,420개)이고,
사내 11항목 체계로 이름표를 다시 붙였습니다.
판단 기준은 미탐(놓친 것)입니다. 과탐은 사람이 걸러낼 수 있지만 미탐은
그대로 유출이 되므로, 재현율 > F2 > F1 > 정밀도 순으로 봅니다.

--------------------------------------------------------------------------------
2. 실행 방법
--------------------------------------------------------------------------------
eval/ 디렉토리에서 아래 한 줄만 실행합니다.

    python3 run_all.py --model <모델경로>

소요 시간
  [1/6] OPF 추론      : 모델과 장비에 좌우됩니다. 3,000건이면 수십 분이
                        걸릴 수 있습니다. 먼저 --smoke 로 50건만 돌려
                        기동을 확인한 뒤 전량을 돌리기를 권합니다.
  [2/6]~[6/6]         : 합계 약 1초 (3,000건, 개발 장비 실측).

예측 JSONL 이 이미 있으면 추론을 건너뜁니다.
    python3 run_all.py --skip-opf
    python3 run_all.py --pred results/baseline_untyped_preds.jsonl

화면에 나오는 모든 줄은 results/REPORT_<날짜_시각>.txt 에도 그대로 적힙니다.
파일 반출이 막혀 있으면 화면을 그대로 보여주면 됩니다.
한 단계라도 실패하면 그 자리에서 멈추고, 실패한 명령줄과 복구 방법 한 줄을
출력합니다. 다음 단계로 넘어가지 않습니다.

--------------------------------------------------------------------------------
3. 화면에서 무엇을 보는가
--------------------------------------------------------------------------------
[1/6] OPF 추론
      모델을 돌려 예측 스팬 JSONL 을 만듭니다. --skip-opf / --pred 면 생략.
[2/6] 성능지표 (표준 정의)
      TP/FN/FP 와 재현율·정밀도·F1·F2. 세 기준(strict/partial/type)을 나란히
      찍습니다. 보고용 정본은 partial 입니다.
[3/6] 문서 단위 미탐
      스팬이 아니라 문서 단위로, 한 건이라도 놓친 문서가 몇 개인지 봅니다.
[4/6] 규칙 레이어
      주민등록번호·외국인등록번호·여권번호·운전면허번호 4종을 정규식으로
      따로 잡아 예측 JSONL 을 만듭니다.
[5/6] 하이브리드 비교
      OPF 단독 / 규칙 단독 / 둘의 합집합을 같은 축에서 비교합니다.
      합집합 병합 규칙은 변경 전(넓은 쪽 채택)과 후(구간 합집합)를 병기합니다.
[6/6] 미탐·과탐 예시
      숫자가 아니라 실물입니다. 놓친 값과 앞뒤 문맥을 6개 버킷(A~F)으로
      추려 보여줍니다.
맨 끝의 "요약" 블록만 읽어도 보고가 됩니다.

--------------------------------------------------------------------------------
4. 코드 역할
--------------------------------------------------------------------------------
사용하는 것
  run_all.py                   단일 진입점. 아래 5개 스크립트를 순서대로 호출
  scripts/standalone_metrics.py 예측 스팬만으로 전 지표 산출 ([2/6])
  scripts/doc_level_miss.py     문서 단위 미탐 집계 ([3/6])
  scripts/rule_layer.py         고유식별 4종 정규식 탐지 ([4/6])
  scripts/hybrid_merge.py       OPF/규칙/합집합 비교 ([5/6])
  scripts/dump_examples.py      미탐·과탐 실사례 추출 ([6/6])
  data/ss_pii_testset_ko_v1.json 정본 3,000건. 모든 단계의 정답
  data/eval_corp_labels.jsonl   추론 입력(사내 11항목 라벨)
  data/eval_opf_labels.jsonl    추론 입력(OPF 5라벨). typed 평가용
  data/smoke_corp_50.jsonl      스모크 50건 입력 (--smoke)
  results/REPORT_*.txt          이번 실행의 화면 전량 기록
  RUNBOOK.txt                   단계를 손으로 나눠 칠 때 쓰는 원본 명령 모음

이번 실행에서 쓰지 않는 것
  scripts/aggregate_recall.py   입력이 opf eval 하니스의 metrics JSON 2종인데,
                                이번엔 하니스 없이 예측 스팬만으로 지표를 내는
                                standalone_metrics.py 로 대체했습니다
  scripts/fp_breakdown.py       과탐을 3버킷으로 세는 집계표. 화면에서는
                                dump_examples.py 의 C·D 버킷 실사례로 대신합니다
  scripts/build_probe_set.py    부분 발화 프로브셋 300건 생성기. 산출물이
                                data/ 에 이미 있어 다시 만들 필요가 없습니다
  scripts/build_review_sheet.py 사람이 눈으로 검수할 CSV 300건 표집기.
                                화면 보고가 아니라 오프라인 검수용입니다
  configs/viterbi_baseline.json opf eval 의 운영점(임계값) 조정 파일 3종.
  configs/viterbi_recall_up.json   이번 실행은 기본 운영점 한 가지만 돌립니다.
  configs/viterbi_precision_up.json 운영점 비교는 RUNBOOK [7] 로 따로 합니다
  data/probe_partial_utterance*.jsonl 프로브셋. 버킷 E 는 프로브셋에 대한 OPF
                                예측이 따로 있어야 채워지므로 이번엔 비웁니다

--------------------------------------------------------------------------------
5. 알려진 한계
--------------------------------------------------------------------------------
- 테스트셋은 전량 합성입니다. 실제 상담 로그로는 검증하지 않았습니다.
- 규칙 레이어가 고유식별 4종에서 100%를 내는 것은, 합성 데이터의 번호 형식이
  규칙적이기 때문입니다. 실제 로그의 표기 흔들림에는 같은 수치가 나오지
  않습니다.
- 표집이 라벨 다양성 우선이라 PII 밀집 문서로 편중돼 있습니다. 원천 풀은
  행당 7.15개인데 표집된 3,000행은 행당 15.99개입니다. 실제 분포보다 PII 가
  두 배 이상 빽빽한 문서를 재고 있는 셈입니다.
- 정답의 값은 가명으로 치환돼 있어 실제 인명·주소 분포와 다릅니다.
- 이 수치는 한 모델·한 운영점의 결과이며, 도입 판단의 근거 전부가 아닙니다.
